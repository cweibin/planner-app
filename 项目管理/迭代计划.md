## 1. 迭代计划概述

### 1.1 敏捷开发框架

```
项目周期: 16 周
迭代周期: 2 周
迭代总数: 8 个 Sprint
迭代评审: 每个 Sprint 结束
回顾会议: 每个 Sprint 结束
发布节奏: Sprint 2 (MVP) → Sprint 4 (Beta) → Sprint 8 (Release)
```

### 1.2 迭代计划总览

| Sprint | 时间周期 | 主要目标 | 关键交付 | 里程碑 |
|--------|----------|----------|----------|--------|
| Sprint 0 | W1-W2 | 项目初始化 | 项目框架、环境配置 | M1 |
| Sprint 1 | W3-W4 | 用户+任务基础 | 用户认证、任务CRUD | - |
| Sprint 2 | W5-W6 | 日程+MVP完善 | 日程管理、基础功能 | M2 |
| Sprint 3 | W7-W8 | 习惯+统计 | 习惯追踪、基础统计 | - |
| Sprint 4 | W9-W10 | 高级功能 | 看板、重复、导出 | M3 |
| Sprint 5 | W11-W12 | 同步+离线 | 多端同步、离线支持 | - |
| Sprint 6 | W13-W14 | 优化+测试 | 性能优化、安全加固 | M4 |
| Sprint 7 | W15-W16 | 发布准备 | 全面测试、文档 | M5 |

## 8. 迭代管理规范

### 8.1 迭代流程

```
┌────────────────────────────────────────────────────────────────────┐
│                        Sprint 迭代流程                              │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  Day 1-2: Sprint Planning    │  Day 3-10: Development            │
│  ├── 故事评审                 │   ├── 每日站会 (15min)           │
│  ├── 任务分解                 │   ├── 代码开发                   │
│  ├── 工作量估算               │   ├── 代码审查                   │
│  └── Sprint 目标确认         │   └── 持续集成                   │
│                             │                                    │
├─────────────────────────────┼────────────────────────────────────┤
│                            │                                     │
│  Day 11: Sprint Review      │  Day 12: Sprint Retrospective    │
│  ├── 演示可工作软件          │   ├── 回顾总结                   │
│  ├── 收集反馈                │   ├── 问题分析                   │
│  └── 验收故事                │   └── 改进计划                   │
│                            │                                     │
└─────────────────────────────┴────────────────────────────────────┘
```

### 8.2 每日站会 (Daily Standup)

**时间**: 每天上午 10:00
**时长**: 15 分钟
**参与人**: 全体开发人员

**每人三个问题**:
1. 昨天完成了什么？
2. 今天计划做什么？
3. 有什么阻碍或需要帮助？

### 8.3 故事点估算

| 故事点 | 描述 | 示例 |
|--------|------|------|
| 1 | 非常简单，1-2 小时 | 修复小 bug |
| 2 | 简单，半天内完成 | 简单页面调整 |
| 3 | 中等，1-2 天 | 新增简单功能 |
| 5 | 复杂，3-5 天 | 新增带逻辑的功能 |
| 8 | 非常复杂，1 周以上 | 全新模块开发 |

### 8.4 完成定义 (Definition of Done)

每个任务必须满足以下条件才能标记为完成：

- [ ] 代码已实现
- [ ] 代码已审查通过
- [ ] 单元测试已编写
- [ ] 本地测试通过
- [ ] 文档已更新（如有需要）
- [ ] 无 P0/P1 级别 Bug
- [ ] 代码已合并到主分支

### 8.5 迭代评审检查表

**功能验收**
- [ ] 用户故事全部完成
- [ ] 验收标准全部满足
- [ ] 无严重 Bug

**质量验收**
- [ ] 代码审查通过
- [ ] 单元测试覆盖率达标
- [ ] 性能指标达标

**文档验收**
- [ ] 相关文档已更新
- [ ] API 文档已同步
- [ ] 变更日志已记录
