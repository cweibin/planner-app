# Planner App 部署流程

> 本文档是本项目到阿里云服务器（`47.110.228.189` / `myai.yun`）的**标准部署操作手册**，以后每次部署按此执行。
> 部署方式：本地构建后通过 SSH 上传产物到服务器，再用 Docker Compose / Nginx 生效。

---

## 0. 环境与约定

| 项 | 值 |
|----|----|
| 服务器 | 阿里云 `47.110.228.189`（域名 `myai.yun`，已配 HTTPS） |
| SSH 用户 | `root`（已配置免密登录） |
| 部署用户 | `admin` |
| 项目根 | `/home/admin` |
| 服务器内存 | 1.9GB RAM + 2GB Swap（**不足以在服务器上构建前端，必须本地构建**） |
| 后端代码目录 | `/home/admin/deploy/app`（**代码以 bind mount 挂载进容器，改完即生效**） |
| Compose 文件 | `/home/admin/deploy/docker-compose.yml` |
| 生产环境变量 | `/home/admin/deploy/.env.prod`（**含生产凭证，切勿覆盖/提交**） |
| 容器 | `deploy-api-1`（FastAPI，`127.0.0.1:18000->8000`）、`deploy-db-1`（PostgreSQL 15） |
| Web 前端静态站点 | `/var/www/planner-web`（Nginx 端口 `8081`，React 前端） |
| 移动端 H5 静态站点 | `/var/www/planner-mobile`（Nginx 端口 `8082`，uni-app H5） |

### Nginx 架构

```
用户访问 https://myai.yun/
  → Nginx 443 (SSL)
    → /       → proxy_pass http://127.0.0.1:8082  (移动端 H5)
    → /api/   → proxy_pass http://127.0.0.1:18000 (FastAPI 后端)

Nginx 内部:
  8082 → root /var/www/planner-mobile  (移动端 H5 静态文件)
  8081 → root /var/www/planner-web     (Web 前端 React 静态文件)
  18000 → FastAPI Docker 容器           (后端 API)
```

**架构关键点**：
- 后端 `api` 容器以 `volumes: - ./app:/app/app` 把宿主机 `/home/admin/deploy/app` 挂载进容器，因此**更新后端代码无需重建镜像**，`docker compose up -d --force-recreate api` 即可生效；只有改 `requirements.txt`（依赖）时才 `--build`。
- 前端（Web / 移动端 H5）**必须在本地构建**，服务器内存仅 1.9GB，在服务器上执行 `npm run build` 会被 OOM Kill。构建后将 `dist` 上传到服务器对应目录即可。

## 1. SSH 免密准备（一次性）

本机公钥加入服务器 `root` 的 `authorized_keys`：

```bash
# 本机执行
cat ~/.ssh/id_ed25519.pub
```
在服务器上（用现有登录方式）：
```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '<上面公钥内容>' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```
之后即可 `ssh root@47.110.228.189` 免密登录。

> 若暂未配免密，可临时用密码 + `SSH_ASKPASS`（macOS 无 `setsid`，用 Python `start_new_session`）：
> ```bash
> cat > /tmp/askpass.sh <<'SH'
> #!/bin/bash
> echo "$PLANNER_SSH_PW"
> SH
> chmod +x /tmp/askpass.sh
> PLANNER_SSH_PW='你的密码' SSH_ASKPASS=/tmp/askpass.sh SSH_ASKPASS_REQUIRE=force DISPLAY=:0 \
>   python3 -c "import subprocess;subprocess.run(['ssh','-o','StrictHostKeyChecking=accept-new','root@47.110.228.189','echo OK'],start_new_session=True)"
> ```
> 为简化，下文统一用 `ssh root@47.110.228.189`（已免密）。

## 2. 后端部署（Python / FastAPI）

适用：改了 `backend/app/**` 下任何代码。

### 2.1 上传代码到服务器

本地执行（tar over ssh，自动排除缓存/虚拟环境/数据库/日志/凭证）：

```bash
cd /Users/cweibin/Desktop/planner-app/backend
tar -czf - --exclude='__pycache__' --exclude='*.pyc' --exclude='.env' \
  --exclude='venv' --exclude='planner.db' --exclude='uvicorn.log' app \
  | ssh root@47.110.228.189 'cd /home/admin/deploy && tar -xzf -'
```

> macOS 的 `tar` 会输出 `LIBARCHIVE.xattr.*` 警告，无害，可忽略。
> 如改了 `requirements.txt`，一并上传：
> ```bash
> cd /Users/cweibin/Desktop/planner-app/backend
> tar -cf - requirements.txt | ssh root@47.110.228.189 'cd /home/admin/deploy && tar -xf -'
> ```

### 2.2 生效

**只改代码（未改依赖）—— 秒级生效，无需重建镜像：**
```bash
ssh root@47.110.228.189 'cd /home/admin/deploy && docker compose up -d --force-recreate api'
```

**改了依赖（requirements.txt）—— 重建镜像：**
```bash
ssh root@47.110.228.189 'cd /home/admin/deploy && docker compose up -d --build api'
```
> `Dockerfile.backend` 已配置清华 pip 镜像（`-i https://pypi.tuna.tsinghua.edu.cn/simple`），重建较快。

### 2.3 验证

```bash
# 容器状态
ssh root@47.110.228.189 'docker ps --format "{{.Names}} {{.Status}}" | grep deploy-api-1'
# 健康检查
curl -s -o /dev/null -w "/api/auth/profile -> HTTP %{http_code}\n" https://myai.yun/api/auth/profile
# 语音接口路由存在性（应 401，非 404）
curl -s -o /dev/null -w "/api/voice/tasks -> HTTP %{http_code}\n" -X POST https://myai.yun/api/voice/tasks
```

期望：`/api/auth/profile` 与 `/api/voice/tasks` 均返回 **401**（未带 token 的正常响应）。

## 3. Web 前端部署（React，`frontend/web`）

适用：改了 `frontend/web/**`。

> ⚠️ 服务器内存不足，**必须本地构建后上传 dist**。

```bash
# 1) 本地构建
cd /Users/cweibin/Desktop/planner-app/frontend/web
npm install && npm run build
# 产物在 dist/

# 2) 上传 dist 到服务器
tar -czf - --exclude='._*' -C dist . \
  | ssh root@47.110.228.189 \
    'rm -rf /var/www/planner-web && mkdir -p /var/www/planner-web && cd /var/www/planner-web && tar -xzf -'

# 3) 清理 macOS 元数据 + 修复权限 + 重载 Nginx
ssh root@47.110.228.189 \
  'chown -R root:root /var/www/planner-web && find /var/www/planner-web -name "._*" -delete && nginx -t && systemctl reload nginx'
```

## 4. 移动端 H5 部署（uni-app，`frontend/mobile`）

适用：改了 `frontend/mobile/**`（含 `voice-create` 等页面）。

> ⚠️ 服务器内存仅 1.9GB，**必须本地构建后上传 dist**（在服务器上 `npm run build:h5` 会被 OOM Kill）。
> 移动端 H5 部署到 `/var/www/planner-mobile`（端口 8082），**不是** `/var/www/planner-web`。

```bash
# 1) 本地构建 H5 产物（后端地址用 VITE_API_BASE 注入）
cd /Users/cweibin/Desktop/planner-app/frontend/mobile
VITE_API_BASE="https://myai.yun/api" npm run build:h5
# 产物在 dist/build/h5/

# 2) 上传 dist 到服务器
tar -czf - --exclude='._*' -C dist/build/h5 . \
  | ssh root@47.110.228.189 \
    'rm -rf /var/www/planner-mobile && mkdir -p /var/www/planner-mobile && cd /var/www/planner-mobile && tar -xzf -'

# 3) 清理 macOS 元数据 + 修复权限 + 重载 Nginx
ssh root@47.110.228.189 \
  'chown -R root:root /var/www/planner-mobile && find /var/www/planner-mobile -name "._*" -delete && nginx -t && systemctl reload nginx'
```

### 4.1 验证

```bash
curl -s -o /dev/null -w "H5 首页 -> HTTP %{http_code}\n" https://myai.yun/
curl -s -o /dev/null -w "API 健康检查 -> HTTP %{http_code}\n" https://myai.yun/api/auth/profile
```

期望：H5 首页返回 **200**，API 返回 **401**（未带 token 的正常响应）。

```bash

d = json.loads(p.read_text())
```

## 7. 回滚

- **后端**：代码回退（git checkout 旧版本后重新上传）→ `docker compose up -d --force-recreate api`。
- **compose 改动**：服务器存有 `docker-compose.yml.bak.<时间戳>`，可 `cp docker-compose.yml.bak.* docker-compose.yml` 后 `docker compose up -d --force-recreate api`。
- **前端**：保留上一次 `dist` 备份后再覆盖，或重新构建旧版本发布。

## 8. 注意事项

1. **绝不覆盖** `/home/admin/deploy/.env.prod`（生产凭证：GLM/Aliyun/数据库密码）。上传命令已排除 `.env`。
2. **绝不提交** `backend/.env`、`backend/venv/`、`*.tar.gz`、`project.private.config.json` 到 git（已在 `.gitignore`）。
3. 后端 `api` 容器以 bind mount 挂载 `/home/admin/deploy/app`，所以该目录必须保留**完整的 app 包**（`__init__.py / api / core / models / schemas / services / main.py …`）。
4. `docker compose` 的 `version` 字段已废弃（会有 warning），可忽略。
5. 服务器无 `rsync`，统一用 `tar over ssh` 上传。
6. 服务器内存仅 1.9GB，**前端构建必须在本地完成**，服务器上构建会被 OOM Kill。已添加 2GB Swap 但仍不足以构建前端。
7. Web 前端部署到 `/var/www/planner-web`（端口 8081），移动端 H5 部署到 `/var/www/planner-mobile`（端口 8082），两者是**不同的目录**，不要混淆。
8. `https://myai.yun` 对外服务的是**移动端 H5**（代理到 8082），Web 前端需通过 `http://47.110.228.189:8081` 访问。
9. 微信开发者工具登录需手机扫码，无法自动化；CLI 调用需在「设置 → 安全设置」开启服务端口。
10. macOS 的 `tar` 会附带 `._*` 扩展属性文件，上传后需执行 `find ... -name "._*" -delete` 清理。
